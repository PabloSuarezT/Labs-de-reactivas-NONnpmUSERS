# Respuestas Pregunta 1 (P1) - Introducción a React

## a) ¿Qué es un componente en React? ¿En qué se diferencia de una función común de TypeScript?

Un **componente en React** es la unidad fundamental, independiente y reutilizable de la interfaz de usuario. En el React moderno, un componente es una función de TypeScript/JavaScript que recibe un objeto con propiedades (`props`) y retorna elementos de React descritos sintácticamente en JSX/TSX.

### Diferencias con una función común de TypeScript:
1. **Retorno y Propósito**: Un componente retorna elementos JSX que representan la estructura visual de la interfaz. Una función común de TypeScript realiza cálculos o transformaciones de datos arbitrarios y puede retornar cualquier tipo de dato (`number`, `string`, `object`, `void`, etc.).
2. **Ciclo de vida y Motor de React**: Los componentes son gestionados por el motor de React. React controla cuándo invocarlos, administra su estado interno mediante **Hooks** (`useState`, `useEffect`) y coordina la actualización del DOM mediante la reconciliación del Virtual DOM. Una función común la invoca el desarrollador explícitamente y se ejecuta sincrónicamente sin reactividad ni Hooks.
3. **Firma y Convención de nombres**: Los componentes deben nombrarse obligatoriamente en **PascalCase** (por ejemplo, `<BakemonDisplay />`) para que el compilador de JSX los diferencie de las etiquetas HTML nativas (`<div />`), y reciben un único parámetro de entrada correspondiente a sus `props`.

## b) ¿Cuál es la diferencia entre props y state? ¿Quién puede modificar cada uno, y qué ocurre en la página cuando cambian?

### Props (Propiedades):
- Son los datos de entrada pasados de un componente padre a un componente hijo (flujo unidireccional de datos).
- Son **inmutables** para el componente hijo que las recibe.
- **Quién las modifica**: El componente hijo no puede modificar sus propias `props`. Solo el componente padre que las pasa puede modificarlas al re-renderizarse y suministrar nuevos valores.

### State (Estado):
- Es la memoria interna y local del componente, utilizada para guardar información que puede cambiar a lo largo del tiempo debido a interacciones del usuario o eventos.
- Es **mutable indirectamente** a través de su función actualizadora (por ejemplo, `setCount`).
- **Quién lo modifica**: El propio componente que declara el estado es el encargado de actualizarlo usando la función provista por hooks como `useState`.

### ¿Qué ocurre en la página cuando cambian?
Cuando las `props` o el `state` de un componente cambian, React detecta esta modificación y programa un **re-renderizado** del componente y de su árbol de hijos. Durante este proceso, React genera un nuevo Virtual DOM, lo compara con el anterior (reconciliación) y aplica de forma eficiente únicamente los cambios necesarios sobre el DOM real del navegador, actualizando la vista sin recargar la página.

## c) ¿Qué diferencia semántica tiene JSX frente a HTML plano? Ejemplifique con `className` y el uso de `{ }` para insertar expresiones.

### Diferencia semántica:
HTML plano es un lenguaje de marcado interpretar por el navegador para estructurar un documento estático. **JSX (JavaScript XML)** es una extensión sintáctica de JavaScript/TypeScript que se transpila a código JS ejecutable (llamadas como `React.createElement` o `_jsx()`). Por lo tanto, JSX es código TypeScript que construye objetos de JavaScript representando la UI.

### Ejemplos de diferencias clave:

#### 1. Atributos en CamelCase (`className`):
Dado que JSX se transforma en propiedades de objetos de JavaScript, no se pueden usar palabras reservadas de JS como nombres de atributos HTML.
- **En HTML plano**: Se usa `class`.
  ```html
  <div class="bakemon-card"></div>
  ```
- **En JSX**: `class` es palabra reservada en JS para definir clases, por lo que JSX exige `className`.
  ```tsx
  <div className="bakemon-card"></div>
  ```

#### 2. Inserción de expresiones con llaves `{ }`:
En HTML plano, los valores e intercalaciones son texto literal. En JSX, envolver cualquier expresión entre llaves `{}` permite evaluar código TypeScript/JavaScript dinámico en tiempo de ejecución.

- **Ejemplo de expresiones en JSX**:
  ```tsx
  // Insertar variables y expresiones matemáticas
  <h2>{bakemon.name.toUpperCase()} (# {bakemon.id})</h2>
  
  // Expresiones condicionales
  <p>Status: {bakemon.height > 10 ? 'Grande' : 'Pequeño'}</p>
  
  // Renderizado dinámico de arreglos con .map()
  <ul>
    {bakemon.types.map((t) => (
      <li key={t.slot}>{t.type}</li>
    ))}
  </ul>
  ```
